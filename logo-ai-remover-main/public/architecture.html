03. Comprehensive Task-by-Task Deep Dive

Task 1

AI Video Watermark Removal Pipeline (Gemini & Veo Marks)

Removes translucent static and moving AI watermarks (such as Google Gemini corner sparkles and Veo marks) from video files while preserving original resolution, frame rate, audio, and color spaces without blurring.

Sequential Execution Steps:

Step 1.1 Client Preflight & Health Probe
The frontend fetches /api/video-worker to discover the worker origin (defaults to http://127.0.0.1:5000). It executes a preflight GET /health to ensure FFmpeg, FFprobe, and models are available before sending files.
Step 1.2 File Validation & Probe Analysis
The file is uploaded via POST /api/video/process. In main.py, ffprobe inspects the container: duration (≤60s default, max 500MB), resolution, codec (H.264/HEVC/VP9), pixel format (e.g. yuv420p), and color matrix (bt709, bt601, smpte170m).
Step 1.3 Multi-Frame Opacity Calibration
processor.py extracts 16 sample frames across the video using FFmpeg. It computes white response log distance: R = -ln(max(255 - gray, 12)). It correlates these samples against cached 16-bit alpha_mask.png templates (sizes 36px, 96px, etc.) to detect watermark position and calculate the exact alpha gain.
Step 1.4 Dual-Subprocess Streaming (Decode → Inpaint → Encode)
Two concurrent FFmpeg processes are spawned and connected via standard pipes (pipe:1 to Python to pipe:0). The decoder streams raw video frames. Python processes each frame in memory and pipes the clean raw frame directly into the x264 encoder.
Step 1.5 Inverse Alpha Restoration & Texture Grain Synthesis
For each frame:
1. Inverse Alpha: restored = (patch - 255.0 * α) / (1.0 - |α|)
2. DC Brightness offset compensation eliminates white smudging over flat backgrounds.
3. High-opacity core pixels are inpainted using Navier-Stokes (cv2.INPAINT_NS).
4. Local Gaussian noise matching the standard deviation of surrounding pixels is injected so the restored patch does not look unnaturally smooth.
5. Temporal stabilization dampens inter-frame flicker: corr = 0.8 * corr + 0.2 * last_corr.
Step 1.6 Lossless Audio & Metadata Multiplexing
The encoding FFmpeg process maps the original audio track without re-encoding (-c:a copy via -map 1:a?), copies container metadata (-map_metadata 1), and preserves timebase timestamps (-copyts).

Critical Constraints & Gotchas in Video Processing:
  • Windows Asyncio Subprocess NotImplementedError: On Windows, calling asyncio.create_subprocess_exec under Uvicorn's default SelectorEventLoop crashes with NotImplementedError. All FFmpeg subprocesses MUST be spawned using standard subprocess.Popen inside worker threads via asyncio.to_thread.
  • Chrome Private Network Access (PNA): When the frontend is hosted on http://localhost:5678 and calls http://127.0.0.1:5000, Chrome sends Access-Control-Request-Private-Network: true. Without allow_private_network=True in Starlette's CORSMiddleware, Chrome fails the preflight with 400 Bad Request and flags the worker as offline!
  • Odd Dimension Chroma Subsampling: yuv420p requires even pixel dimensions (both width and height divisible by 2). If an odd-dimension video is piped, FFmpeg crashes unless bitmask alignment (& ~1) or yuv444p fallback is enforced.
  • Color Space Shifting: Converting YUV → RGB → YUV introduces perceptible color shifts (BT.709 vs BT.601). The engine uses native_yuv mode to modify only the Y luma channel and corresponding U/V chroma coordinates whenever possible.
Task 2

Production AI Background Removal Engine (BiRefNet / IS-Net / Design Mode)

State-of-the-art background removal matching commercial tools (remove.bg). Combines layout mode classification, deep neural segmentation, component union retention, hole healing, and sub-pixel guided matting.

Sequential Execution Steps:

Step 2.1 EXIF Normalization & Native Resolution Decoding
The image is decoded using PIL and transposed according to EXIF tags (ImageOps.exif_transpose). Palette images ('P') and CMYK/Grayscale images are normalized to RGBA/RGB without downsampling.
Step 2.2 Mode Detection First: Design Mode vs Subject Mode
CRITICAL INNOVATION: Before any face detection runs, detect_design_mode_and_cards() inspects the image for UI card structures, multi-column collages, and screenshots. It clusters connected components. If ≥2 consistent rectangular cards are detected, it enters Design Mode and generates antialiased rounded container masks (2x supersampling). Faces inside card photos are protected and NEVER isolated!
Step 2.3 Modern Face Detection via OpenCV YuNet DNN
In Subject Mode, the engine detects human faces using OpenCV's YuNet ONNX model (FaceDetectorYN). This replaces obsolete Haar cascades and reliably detects side profiles, tilted heads, and children's faces.
Step 2.4 Neural Segmentation (IS-Net / BiRefNet / U2-Net)
The image is fed to Rembg ONNX Runtime sessions. The model chain selects isnet-general-use → birefnet-general → u2net_human_seg. Highly precise edge probabilities are output as raw alpha.
Step 2.5 Hole & Small Notch Healing
fill_holes_and_small_notches() traverses the contour hierarchy (cv2.RETR_CCOMP). Any hole fully enclosed by foreground (e.g. white shirts, reflective skin, eyeglasses) is filled back to opaque (255), while natural gaps (between arms and torso, or between legs) remain transparent.
Step 2.6 Connected Component Union Selection
Replaces old arbitrary fh * 4.0 height truncation. It keeps any component that intersects or connects to face regions, preserving long dresses, shoes, held objects, and secondary family members while dropping floating background text, logos, and UI buttons. Proximity expansion is constrained to 8px to prevent grabbing decorative circular background rings or mandalas.
Step 2.7 Fast Guided Filter Matting & Telea Halo Decontamination
1. Core subject is locked at 255 (solid).
2. A narrow 3px boundary transition zone is refined using He et al.'s Fast Guided Filter (sub-sampling factor s=2), generating hair-strand alpha in <60ms.
3. Semi-transparent boundary pixels (alpha 5..240) are inpainted via Telea (cv2.INPAINT_TELEA) to eliminate color fringing and background light bleed.

Critical Constraints & Gotchas in Background Removal:
  • Memory Explosion on High-Res (6000px): Running PyMatting or Laplacian matting matrices on full 6000×4000 images requires >16 GB RAM and crashes the process. The Fast Guided Filter solves this by computing covariance on a 2x downsampled guide (s=2) and evaluating linear coefficients (a * I + b) at native resolution in under 60ms!
  • Over-aggressive Face Isolation: If a family photo or an ad banner with text is processed with standard u2net_human_seg, it treats the main face as the only subject and deletes children, held products, or dresses. The Design Mode classifier and Component Union selector solve this.
  • Decorative Background Elements: If the proximity dilation radius is too large (>20px), decorative background rings (like mandalas or circular badges behind a person) get falsely merged into the foreground. Limiting dilation to 8px cleanly separates the person from the graphic.
Task 3

PDF Document Watermark & Stamp Removal Engine (Vector & Raster)

Cleans watermarks, confidentiality stamps, draft banners, and colored ink marks from PDF documents and scanned legal paperwork. Operates in two distinct modes: lossless vector AST content stream surgery and raster scanned paper reconstruction.

Sequential Execution Steps:

Step 3.1 Document Ingestion & Classification
PDFs or image documents are received at /api/pdf/upload. pdf_engine.py evaluates whether each page is a Native Vector PDF or a Scanned Paper Document (analyzing grayscale mean > 185 and HSV saturation mean < 35).
Step 3.2 Vector AST Stream Analysis (PyMuPDF / pypdf)
For native PDFs, page.get_texttrace() parses font spans, opacities, and angles. Text matching watermark keywords (DRAFT, CONFIDENTIAL, SAMPLE, COPY) with diagonal direction (dir[1] > 0.08) or opacity < 0.92 is flagged.
Step 3.3 Lossless ContentStream Surgery
Instead of rasterizing and destroying vector text sharpness, pypdf's ContentStream traverses operators: q (save state), gs (graphics state/opacity), Tj/TJ (show text), Do (XObject form/image). Targeted watermark operations are pruned directly from the byte stream. Page vector quality remains 100% untouched and file size remains minimal.
Step 3.4 Scanned Paper Separation (HSV & TopHat Filtering)
For scanned paper pages:
1. PyMuPDF renders the page at 150..300 DPI (page.get_pixmap()).
2. HSV color segmentation separates colored stamp ink (red/blue "APPROVED" or "PAID" stamps) from high-density black text.
3. Morphological TopHat (white tophat with elliptical kernels) extracts faint diagonal gray watermark patterns.
4. Text stroke masks are subtracted so underlying document letters are never erased.
5. Inpainted clean page is re-compressed and packed into the output PDF.

Critical Constraints & Gotchas in PDF Cleaning:
  • Rasterization Trap: Many naive tools convert PDF pages into PNGs, inpaint them, and reassemble them into a new PDF. This turns a 200 KB crisp vector document into a 45 MB blurry image-based PDF. Bellix inspects the PDF operator tree first and performs direct vector surgery whenever possible.
  • Overlapping Text Stems: When a diagonal stamp crosses over a black letter "T" or "H", a simple color threshold can leave white gaps in the letter. Bellix computes a strict luminance threshold (gray < 85) to preserve the original high-contrast document ink.
  • Multi-tenant Job Sidecar Security: Document uploads write an isolated .owner sidecar file containing the user ID. Requests to fetch or clean pages verify that owner == request.state.user_id to prevent cross-account document access.
Task 4

High-Precision Image Watermark & Logo Inpainting

Removes transparent AI stamps, text logos, stock photo copyright text, and corner icons from single images with sub-pixel inverse blending and deep neural inpainting.

Sequential Execution Steps:

Step 4.1 Target Localization (Corner vs Manual vs Template)
If a manual bounding box is passed via box=[x, y, w, h], the region is clipped. Otherwise, multi-scale template matching searches corners (lower-right, lower-left, upper-right) for known AI sparkle signatures across scales 12px..96px.
Step 4.2 Inverse Alpha Blending Reconstruction
When the watermark opacity map is known, mathematical inverse alpha restoration runs: I_original = (I_watermarked - 255 * α) / (1 - α). Because this inverts the exact blending formula, the underlying image detail is perfectly recovered without any neural guessing or blur!
Step 4.3 Neural LaMa (Large Mask Inpainting) Fallback
For solid/opaque watermarks, stock photo text, or large logos where underlying pixels were destroyed, the engine loads big-lama.pt (Fast Fourier Convolution neural network) via lama_residual.py to hallucinate realistic background textures and structural lines.

Gotchas & Considerations:
  • Weight Size: big-lama.pt is ~200MB. The worker uses on-demand lazy loading (USE_LAMA=1) to keep startup time under 1 second and idle memory consumption under 120MB.
  • Edge Feathering: Opaque mask edges produce sharp seams if not blended. lama_residual.py applies a 14px distance-transform feathering gradient to blend neural inpainting smoothly into surrounding photographic noise.
Task 5

Authentication, Quotas, Job State & Billing Lifecycle

Manages user identity, subscription tiers, guest rate limits, and atomic credit deductions across long-running asynchronous media processing jobs.

Sequential Execution Steps:

Step 5.1 Session Resolution & Guest Fallback
Requests pass through accountFetch() in the frontend, attaching Authorization: Bearer <token> or session cookies. In billing_access.py, if Supabase credentials are not set or user is anonymous, it defaults to local-guest-user so local development and guest users can test the studio seamlessly.
Step 5.2 Two-Phase Credit Reservation & Settlement
To prevent race conditions on long video encodes:
1. Reserve: reserve_video(user_id, request_key) locks 1 credit before encoding begins.
2. Process: Worker executes the job.
3. Settle: Upon successful export, settle(user_id, request_key, success=True) commits the deduction. If processing fails or is aborted, success=False immediately refunds the credit.
Step 5.3 Payment Gateways & Webhook Signature Verification
Razorpay orders are created via /api/payments/create-order. Client checkout completes and sends signatures to /api/payments/verify, which computes crypto.createHmac("sha256", secret).update(order_id + "|" + payment_id).digest("hex") to prevent forged payments.

Task 6

Local Development, Cross-Platform Orchestration & IPC Architecture

Ensures that both the Node.js Next.js frontend and Python FastAPI backend can be started with a single cross-platform command on Windows, macOS, and Linux without shell-specific syntax errors.

Key Orchestration Components:

Script scripts/start-worker.js (Intelligent Python Discovery)
Node script that auto-locates Python virtual environments. It checks watermark-backend/.venv/Scripts/python.exe (Windows) and watermark-backend/.venv/bin/python (Linux/Mac). If no venv exists, it falls back to system python3 or python, verifies port 5000 is open, and launches Uvicorn with auto-reload.
Script scripts/check-environment.js (Automated Health Preflight)
Runs via npm run check. Tests:
• Python version (≥3.9)
• Installed packages (FastAPI, Rembg, OpenCV, PyMuPDF)
• FFmpeg & FFprobe on system PATH
• Port 5000 availability
• Live worker health endpoint responsiveness
NPM package.json Concurrently Scripts
Windows PowerShell throws syntax errors on the POSIX && separator. The unified script:
"dev:all": "concurrently -k -n \"next,worker\" -c \"cyan,magenta\" \"npm run dev\" \"npm run worker\"" runs both servers concurrently with color-coded logs and graceful shutdown.
