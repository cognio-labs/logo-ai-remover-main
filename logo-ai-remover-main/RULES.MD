# Bellix.us — Engineering rules

These guide future implementation. Existing gaps are tracked in [TASKS.MD](TASKS.MD).

1. Preserve the Lovable warning in [AGENTS.md](AGENTS.md); never rewrite published history or force-push the connected branch.
2. Inspect the worktree before edits and preserve unrelated user changes.
3. Follow the actual TanStack/Vite application; archived Next.js prompts are not current instructions.
4. Distinguish implemented, simulated, proposed and production-verified behavior.
5. Associate originals, masks, previews and results with the correct job. Never substitute demo media or another job's output on failure.
6. Treat client roles, credits, filenames and IDs as untrusted; enforce privileges on the backend.
7. Validate server-side limits and reflect them in uploaders. Preserve aspect ratio, frame order and audio identity unless explicitly transforming them.
8. Do not duplicate plugins supplied by `@lovable.dev/vite-tanstack-config`; follow `vite.config.ts`.
9. Reuse shared UI and the current light/rose theme. Scope visual direction changes deliberately.
10. Keep secrets, real uploads, runtime outputs and model weights out of commits and privileged keys out of client builds.
11. Update API clients/contracts/tests together and preserve aliases unless deliberately migrated.
12. Run relevant checks from [TESTING.MD](TESTING.MD); report actual results and limitations.
13. Update affected docs, durable decisions in [MEMORY.MD](MEMORY.MD), and open work in [TASKS.MD](TASKS.MD).
14. Deployment config and successful page responses do not prove processing, payment or retention behavior.

Documentation-only work does not authorize unrelated application fixes or deployment.
